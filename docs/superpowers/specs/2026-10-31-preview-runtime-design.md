# Закрытие рисков preview и обновление runtime

Пользователь поручил выполнить следующий этап аудита с агентами, в отдельной
ветке, без изменения `master`. База — `security/privacy-audit`, `91b3cdc`.

## Результат

Сохранённые `index.html`, bundle и assets не являются доверенными исполняемыми
входами предпросмотра. Сервер нормализует ограниченное описание сцены из `job.plan`,
проверяет TSX существующей AST-политикой и пересобирает артефакты в отдельном
временном кэше. Старые проекты обоих движков продолжают открываться; их файлы,
MOV и пути импорта не изменяются. Некорректное описание отклоняется.

Та же граница действует при повторном рендере: оба движка пересобирают проверенный
plan в приватной временной папке и публикуют только законченный MOV по прежнему
пути. Сохранённые пользовательские HTML/JS/config не читаются как executable.
При ошибке валидации или сборки предыдущий MOV сохраняется.

Для Windows x64 приложение использует закреплённые локальные Node.js и
FFmpeg/FFprobe из `.runtime/`, а не глобальные программы. Архивы, версии,
SHA-256, первичные источники и лицензии перечислены в manifest. Установка проверяет
архив до извлечения и исполняемые файлы до использования. Неполная/повреждённая
установка вызывает ошибку, без fallback на PATH. Уже рабочая версия сохраняется
при неудаче подготовки новой.

## Подходы

Дополнительные ограничения JavaScript в сохранённом HTML не устраняют доверие
исполняемому файлу и создают новые возможности обхода. Выбрана предложенная в
аудите пересборка из проверенного описания. Отключение всего старого preview
разрушило бы необходимую совместимость.

Глобальное обновление Node/FFmpeg меняет окружение пользователя и не обеспечивает
воспроизводимость EXE. Выбран локальный комплект. Неограниченная загрузка `latest`
при каждом запуске также исключена: обновление требует изменения reviewed manifest.

## Интерфейсы и ограничения

- `lib/preview-cache.cjs`: нормализация снимка plan, ключ ревизии, дедупликация
  сборок, ограничение ресурсов, очистка при закрытии сервера; текущие preview URL
  и sandbox/CSP/request policy сохраняются.
- `lib/runtime.cjs`: `runtimeExecutable(name)`, `runtimePaths()` и
  `assertCurrentRuntime()`. Имена: `node`, `ffmpeg`, `ffprobe`.
- `scripts/setup-runtime.cjs`: проверяемая установка закреплённых артефактов.
- `scripts/run.cjs`, launcher и дочерние процессы используют частный Node;
  конвертация кадров, оба рендера и проверки используют частные FFmpeg/FFprobe.
- Бинарники, кэш, временные файлы и пользовательские данные не коммитятся.
- Отдельный системный sandbox и обновление Electron внутри Resolve не входят
  в этот этап. Отсутствие всех возможных уязвимостей не обещается.
- Подготовка EXE следует после этой работы: установка/обновление на чистой Windows,
  подпись и комплект исходников/лицензий распространяемых компонентов проверяются
  на готовом артефакте. Реальная AI-генерация и пользовательские credentials
  для проверки этого этапа не нужны.
