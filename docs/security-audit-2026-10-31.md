# Аудит безопасности и приватности — 31 октября 2026

**Последующий этап:** доверие сохранённым executable preview/render устранено,
Node.js и FFmpeg/FFprobe обновлены в отдельном локальном комплекте.
См. [результаты закрытия рисков](preview-runtime-hardening-2026-10-31.md).
Ниже сохранены находки и результаты исходного аудита ветки `security/privacy-audit`.

## Результат и границы

Проверена публичная история `imyeskela/resolve-assistant`, исходники прототипа,
авторизация, AI-запросы, локальное хранение, выполнение сцен и зависимости.
База проверки — `master` на `87acf60d3ffe9fa9fa4657c6cb490897d12edb3c`.
Исправления находятся в отдельной ветке `security/privacy-audit`; `master`
не изменялся. Это аудит исходников и воспроизводимые локальные проверки,
а не сертификат безопасности готового установщика.

Секреты и личные данные в проверенной публичной истории **не обнаружены**.
Это результат описанных ниже проверок, а не доказательство отсутствия любых
возможных персональных сведений. Реальные токены, хранилище учётных данных,
пользовательские чаты и медиа при проверке не читались. Тесты использовали
синтетические данные и временные каталоги. Запросы генерации в OpenAI не отправлялись.

Плагин передаёт в OpenAI содержимое запроса при отправке сообщения: текст,
историю, исходник сцены и подготовленный видеоконтекст. Он не является полностью
локальным AI-приложением. Состав и локальное хранение описаны в [PRIVACY.md](../PRIVACY.md).

**На момент исходного аудита выпуск EXE был заблокирован:** оставались граница
доверия сохранённому preview и обновление/проверка нативных runtime. Они закрыты
последующим этапом, указанным выше; проверка готового установщика ещё предстоит.

  Отдельная проверка подготовленных к коммиту изменений этой ветки также дала 0.

## Метод проверки

Работа разделена между агентами по публикации/авторизации, хранению и исполнению
сцен; дополнительный агент проводил независимое ревью исправлений. CodeGraph
использован для поиска путей вызовов. Подтверждённые дефекты воспроизведены до
исправления и закреплены регрессионными тестами.

Проверки охватывают:

- отмену OAuth, выход во время refresh, конкурентные запросы и задержки записи;
- подмену дочерних каталогов и всего `jobs` после загрузки; выбранный пользователем
  корень проекта сам может быть junction, но вложенные пути не должны уходить наружу;
- работу реального headless-браузера, preview policy и рендерера на синтетических
  сценах; контрольный локальный UDP-приёмник вместо внешнего адреса;
- минимизацию сериализованного AI-запроса и сохранение намеренно введённого текста;
- видимое уведомление о сохранённом контексте, в том числе без текущего In/Out;
- существующие проверки генерации, миграций, UI и рендера обоих движков.

Итоговый `npm test`: **228 тестов, 226 passed, 0 failed, 2 skipped**.
Два пропуска относятся к созданию file symlink, которое Windows не разрешила
в этом окружении; проверки directory junction выполнены. `npm run check` прошёл:
синтаксис, запуск FFmpeg/FFprobe/browser и инициализация Codex app-server без
генерации. Это подтверждение работоспособности, не отсутствие native CVE.
`git diff --check` не выявил ошибок; `npm audit` — 0 известных npm-уязвимостей.

Первый общий прогон дал 219 успешных тестов, 2 пропуска и 1 ошибку `EPERM` при
Windows `rename`. Аналогичная ошибка возникала в целевом прогоне. Источник
блокировки файла не установлен. В `atomicWrite` добавлен Windows-only ограниченный
повтор для `EPERM`/`EACCES`/`EBUSY`: максимум 6 попыток, всего до 775 мс ожидания.
Исходный файл не удаляется; постоянная ошибка возвращается вызывающему коду.
Шесть синтетических тестов проверяют повтор, сохранение исходных данных и отказ
без повторов для прочих ошибок.

## Что остаётся до распространения EXE

1. **Устранить доверие сохранённым HTML/JS.** Открытие старого job должно строить
   preview, bundle и assets из нормализованного declarative plan или проверенного
   TSX в отдельном кэше. Не исполнять исходные сохранённые HTML/JS и не затирать
   пользовательский job. Проверить вложенные фреймы и native Electron hooks
   в реальном Resolve. До этого импортированные/полученные от других людей папки
   проектов нельзя считать безопасными для предпросмотра.
2. **Обновить и отдельно проверить нативную среду выпуска.** На машине аудита
   Node.js 24.18.1 использует встроенный Undici 7.29.0: npm override его не меняет.
   [Node.js 24.22.1](https://nodejs.org/en/blog/release/v24.22.1) — security release,
   включающий Undici 7.30.1. Для установщика нужна проверенная актуальная версия
   runtime; глобальный Node.js пользователя в этом аудите не заменялся.
3. **Обновить FFmpeg/FFprobe и согласовать их версии.** В текущем окружении
   обнаружены FFmpeg 6.1.1 и FFprobe 4.0.2. Официальный
   [список исправлений FFmpeg](https://www.ffmpeg.org/security.html) содержит более
   поздние исправления. Их достижимость через этот плагин отдельно не доказана.
   Устранение npm advisory не является проверкой безопасности этих бинарников.
4. **Управлять обновлениями браузера и Codex runtime.** Проверенные версии:
   Chrome Headless 156.0.8078.47 и Codex 0.166.0. Нативные пакеты и Chromium/Electron
   внутри Resolve не покрываются `npm audit`. Headless shell не обновляет себя
   автоматически; см. [Chromium Security FAQ](https://github.com/chromium/chromium/blob/main/docs/security/faq.md).
5. **Проверить собранный артефакт на чистой Windows.** Включить установку,
   обновление предыдущей версии с сохранением данных, удаление, manifest/SBOM,
   лицензии бинарников, контрольные суммы и повторный secret scan именно содержимого
   EXE. Готового установщика в рамках этого аудита нет.

## Ограничения и остаточные риски

- Не выполнялся полный захват трафика работающего Resolve и нативного app-server
  с реальным AI-запросом. Не проверены серверные сроки хранения и политика аккаунта.
  Отсутствие нежелательных передач в проверенных исходниках не доказывает отсутствие
  любой телеметрии во всех сторонних бинарниках.
- Сетевая защита сцен — несколько прикладных ограничений, а не изоляция отдельным
  пользователем ОС или firewall. Прямой WebRTC-путь закрыт, но отдельный путь
  через изменённый сохранённый HTML остаётся открытой находкой. Нет гарантии
  против всех возможностей браузера и зависимостей.
- DPAPI защищает credentials в контексте Windows CurrentUser. Программа,
  выполняющаяся под тем же пользователем, остаётся за этой границей доверия.
  История чатов, исходники, речь и кадры хранятся открытыми локальными файлами;
  облачная синхронизация выбранной папки может передавать их независимо от плагина.
- Файловые проверки не являются атомарными handle-based операциями. Остаются
  гонки между проверкой пути и доступом, hardlink и замена обычного каталога
  другим по тому же реальному имени. Закрепление корня действует внутри процесса,
  не заменяет права доступа ОС и не доказывает происхождение JSON-файлов.
- Очередь credentials защищает один экземпляр сервиса; межпроцессной блокировки нет.
- Браузерные тесты проверяют суррогат панели, а не взаимодействие с живым Resolve.
  Нужна дополнительная проверка версии Resolve, входа и реальной отправки контекста
  перед заявлением о готовности массового релиза.

[Undici security advisory GHSA-2m5v-pch6-74hx](https://github.com/nodejs/undici/security/advisories/GHSA-2m5v-pch6-74hx).
