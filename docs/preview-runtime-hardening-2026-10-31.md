# Закрытие рисков preview/render и обновление runtime

Работа выполнена в `security/preview-runtime-hardening` поверх аудита `91b3cdc`.
`master` не изменялся. Цель — подготовить техническую основу для Windows x64 EXE;
сам установщик и публичный бинарный релиз этим изменением не создаются.

## Исполнение сцен

HTTP preview больше не читает `index.html`, bundle и GSAP из сохранённого job.
Он принимает ограниченный снимок `job.plan`, нормализует параметры, проверяет
Remotion TSX существующей AST/import-политикой и собирает файлы установленными
компиляторами в приватной временной папке. В сеть локального preview попадают
только два разрешённых артефакта этой сборки. Папка удаляется; готовые байты
сохраняются в ограниченном кэше памяти: 8 ревизий, 32 МБ, до 2 параллельных сборок.
Повторные запросы одной ревизии используют одну сборку; изменение plan меняет ключ.

Повторный рендер имеет ту же границу: и `renderMotion`, и `renderRemotion`
пересобирают сцену в отдельной временной папке. Сохранённые HTML/JS, `source.tsx`,
`remotion-render.json` и конфигурации сторонних инструментов не исполняются.
Только проверенный готовый MOV копируется через временный файл по прежнему пути
`job/motion.mov`. Ошибка или отмена до публикации сохраняет прежний MOV.
Исходники, metadata, история и пути импорта не переписываются.

`job.plan` остаётся источником сцены. Ручная правка производных HTML/JS/`source.tsx`
на диске больше не изменяет preview/render; для редактирования используется сцена
в приложении. Повреждённый plan отклоняется, а не исполняется через старый HTML.
Поддерживаются прежние HyperFrames plans без поля engine и Remotion plans.

Сохранены прежние нормализаторы, разрешение, дробный FPS, длительность по
видеоконтексту, количество кадров и ProRes 4444 с альфа-каналом. Кадры, речь,
история и исходник в AI-запросах не сокращались. Политика не направлена на
ограничение полезного контекста OpenAI.

Дополнительный smoke выявил, что HyperFrames CLI отвергал десятичный аргумент
FPS. Оба рендера теперь получают рациональную запись того же численного значения:
`29.97` передаётся как `2997/100`, а число `30000/1001` — как `30000/1001`.
Значения не округляются до целых и не переинтерпретируются как ближайший preset.
Реальные MOV для обеих форм проверены по частоте потока и количеству кадров.

## Частный комплект runtime

| Компонент | Версия | Источник |
| --- | --- | --- |
| Node.js Windows x64 | 24.22.2 LTS, встроенный Undici 7.30.1 | [официальный релиз](https://nodejs.org/en/blog/release/v24.22.2) |
| FFmpeg / FFprobe Windows x64 | 9.0.2, одна статическая Gyan essentials сборка | [страница сборок](https://www.gyan.dev/ffmpeg/builds/), [release](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.2) |

Полные URL, SHA-256 архивов и извлечённых файлов, provenance, upstream notices
и ссылки на исходники закреплены в [`runtime-manifest.json`](../runtime-manifest.json).
Архив Node сверён с официальным SHASUMS; FFmpeg — с опубликованной суммой Gyan.
Название essentials не означает снижение качества кодирования ProRes: необходимые
кодеки, фильтры и операции проверяются реальными рендерами.

`npm.cmd run runtime:setup` устанавливает комплект в `.runtime/win32-x64`.
Загрузки ограничены указанными HTTPS-хостами и размером; архив проверяется до
выборочного извлечения. Пути, дубликаты ZIP entries, junction и несовпадения
checksum отклоняются. Проверяются также сохранённые лицензии и README.
До успешной проверки всего комплекта существующая установка не заменяется.
При ошибке публикации выполняется откат; если сам откат невозможен, предыдущие
файлы остаются в recovery-папке для восстановления, не удаляются cleanup.

Launcher, controller, дочерние HyperFrames/Remotion-процессы и преобразование
кадров используют частные executables. Старое `nodePath` в установленном
`runtime.json` не выбирает системный Node. Неполный или изменённый комплект
отклоняется без PATH fallback. PowerShell staging проверяет хеш Node до его
первого запуска. Npm scripts используют `scripts/run.cjs`; глобальный Node нужен
разработчику только для bootstrap/npm. Глобальные Node/FFmpeg и PATH не менялись.
Устаревшие `ffmpeg-static`/`ffprobe-static` удалены из зависимостей.

## Проверки

- До исправления воспроизведены выполнение подменённого сохранённого HTML и
  чтение его при рендере. После исправления HTTP/browser tests не исполняют
  сохранённые inline/bundle/GSAP и самокопирующийся `srcdoc` canary.
- Проверены оба preview, реальные MOV обоих движков и прямой Remotion entrypoint,
  короткие/длинные видеодиапазоны, альфа-формат, отмена, сохранение прежних файлов,
  кэш, смена ревизии и очистка при закрытии.
- Runtime tests проверяют checksum до extraction, повреждения после успешной
  проверки, отсутствие notices, небезопасные пути, ZIP traversal/duplicates,
  отказ замены, откат и сохранение recovery при ошибке отката.
- Реальный launcher подтверждает путь/версию частного Node, отсутствие
  унаследованного синтетического секрета и сохранение exit code дочернего процесса.
- `npm run check` и `npm run stage` прошли. StageOnly подготовил локальную папку
  плагина, не изменяя установленную интеграцию и не запуская Resolve.
- `npm audit`: 0 известных npm-уязвимостей после удаления старых binary packages.
- Дополнительные smoke обоих движков: 640×360, 29.97 FPS, 60 кадров,
  ProRes 4444 / `yuva444p12le`. Декодирование RGBA подтвердило присутствие
  прозрачных, непрозрачных и полупрозрачных пикселей.
- Отдельно проверено, что ошибка удаления временных файлов runtime не пропускает
  освобождение setup lock и не оставляет ложное состояние «установка уже идёт».

Итоговый `npm test`: **256 тестов, 254 passed, 0 failed, 2 skipped**.
Оба пропуска — недоступное создание file symlink в этом окружении Windows;
проверки directory junction выполнены. Gitleaks не обнаружил секретов в
подготовленных изменениях. `.runtime/`, `.codegraph/` и пользовательские данные
исключены из Git.

## Что проверяется при создании установщика

Технические находки этого этапа закрыты в указанной модели угроз. Это не обещание
отсутствия всех будущих уязвимостей и не отдельная изоляция процессом ОС/firewall.
Остаются обычные границы доверия локальным программам того же пользователя,
проверка путей без атомарных OS handles и неизменённый Electron внутри Resolve.
Аварийное завершение может оставить временную сборку в пользовательском TEMP.

Для готового EXE нужны тесты установки/обновления/удаления на чистой Windows и
живом Resolve Studio, сохранение данных, проверка подписи/контрольных сумм,
состава артефакта и лицензий. Сборка FFmpeg — GPL; сохранение LICENSE само по себе
не подтверждает выполнение условий распространения. До публичной публикации
нужно подготовить соответствующий механизм предоставления исходников точной
сборки с зависимостями и build scripts. Manifest явно фиксирует это требование;
публичный комплект исходников этим setup ещё не формируется.

Реальные пользовательские credentials и AI-запросы для этих проверок не использовались.
